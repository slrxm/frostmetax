# FROSTMETA — запуск и публикация

## Что готово

Общий интерфейс сайта, проекты Capacitor Android/iOS, новая иконка, кнопка скачивания,
Google OAuth Authorization Code + PKCE, подтверждённая привязка Steam OpenID 2.0,
сессии и база SQLite, отвязка Steam и удаление аккаунта. Google/Steam пароли не хранятся.
Ключ Steam Web API для OpenID не требуется. Профиль статистики загружается из OpenDota
по проверенному Steam ID, а не по введённому пользователем чужому ID.

## Сервер

Нужен Node.js 24 и постоянный диск. Однопроцессный сервер; SQLite не размещать на временном
диске serverless-хостинга. Для нескольких реплик потребуется общая БД и общее ограничение запросов.

```sh
npm ci
npm run build
cp .env.example .env
node --env-file=.env server/index.mjs
```

В production задать HTTPS `PUBLIC_URL` без пути, например `https://app.example.com`.
HTTPS завершается на доверенном reverse proxy; включать `TRUST_PROXY=true` только за ним.
Сервер обслуживает сайт и API с одного origin. GitHub Pages не выполняет серверный код.
Базу `var/frostmeta.sqlite` резервировать и хранить вне публичной директории.
Встроенный HTTP-клиент использует доступ сервера к Google, Steam и GitHub Pages.

## Google

В Google Cloud Console создать OAuth client типа **Web application**.
Настроить consent screen и тестовых пользователей, пока приложение в режиме testing.
Authorized redirect URI: `https://ВАШ-ДОМЕН/auth/google/callback`.
Для локальной проверки: `http://localhost:3000/auth/google/callback`.
Указать `GOOGLE_CLIENT_ID` и `GOOGLE_CLIENT_SECRET` в переменных сервера.
Секреты не добавлять в git, `app-config.json`, мобильные сборки или чат.
Личная учётная запись Google Cloud и домен владельца ещё не подключены.

## Android и iOS

В `app-config.json` установить `apiBase` в HTTPS origin сервера. Оставить `metaUrl`
указывающим на обновляемый `data.json` GitHub Pages. При отсутствии сервера
поиск/статистика доступны, а авторизация показывает понятное состояние недоступности.
Приложение загружает мету из сети, а не остаётся с данными, включёнными в сборку.
Для первой загрузки без интернета статистика может быть недоступна.

```sh
npm ci
npm run mobile:sync
cd android
./gradlew assembleDebug
```

Тестовый APK: `android/app/build/outputs/apk/debug/app-debug.apk`.
Это debug-подпись, не сборка для магазина. App ID `app.frostmeta.mobile` пока предварительный;
подтвердить его до регистрации в магазинах. Release keystore должен принадлежать владельцу,
его нельзя коммитить. Перед выпуском Android поднять targetSdk согласно требованиям магазина.

iOS: macOS + Xcode + CocoaPods, `npm run mobile:sync`, `npm run ios`, выбрать Team,
проверить bundle ID и Archive. Linux не собирает и не подписывает iOS.
У проектов сгенерированы иконки и splash screens.
В native-приложении вход открывается через системный браузер, затем приложение забирает
одноразовый результат по отдельному секрету. Bearer хранится только в памяти:
после полного закрытия приложения потребуется повторный вход. Для постоянной сессии
следующим шагом использовать Keychain/Android Keystore, не localStorage.

## Магазины и кнопки

Владелец создаёт Apple Developer и Google Play Console, заполняет сведения об операторе,
возрастную категорию, privacy/data safety, загружает подписанные сборки.
Нужно проверить требования Apple к альтернативному входу при использовании Google:
Sign in with Apple пока не реализован. Автоматическое одобрение магазинами не гарантируется.
Проверить платформенную пригодность интерфейса на настоящих устройствах и тестировщиках.

После публикации заполнить `googlePlayUrl` и `appStoreUrl` в `app-config.json`.
Для прямой установки тестового Android APK можно заполнить HTTPS `androidApkUrl`.
Пустые поля отображаются как «скоро», без выдуманных URL и неработающих ссылок.

## Мета

История GitHub подтвердила: запуск 7 ноября 2026 успешен, 25/25 срезов,
однако данные полностью совпадают с 6 ноября; дата файла менялась.
Раньше использовался `winWeek(take:1)` и ежедневное расписание.
Теперь `winDay(take:1)`, расписание каждые 3 часа (UTC, минута 17).
Это частота запросов; реальная частота изменения зависит от STRATZ.

`STRATZ_TOKEN` уже настроен в исходном GitHub Actions, но секрет не доступен локально.
Новый живой запрос `winDay` необходимо подтвердить запуском Update meta после включения
изменений. При несовместимости схемы ошибка появится в Actions, старые данные сохранятся.
Не заменять неработающий источник демонстрационными цифрами.

`checkedAt` — время запроса; `dataUpdatedAt` — последнее фактическое изменение;
`sliceUpdatedAt` — успешная проверка отдельных фильтров; `matches` — объём выборки.
Пустые и некорректные ответы сохраняют прежний срез. Полная ошибка не меняет data.json,
но записывает meta-status.json; workflow завершается ошибкой после сохранения статуса.
При первом переходе с недельной на суточную выборку тренд сбрасывается, а не сравнивает
разные периоды. Повтор того же снимка сохраняет последний содержательный тренд.
GitHub cron может задерживаться. Частая проверка не создаёт новые данные у STRATZ.

## Проверка

```sh
npm test
npm run build
npx playwright test
```

Браузерные тесты проверяют мобильную ширину, поиск, окно скачивания, состояние входа,
пустые данные и offline-ошибку. Серверные тесты проверяют Steam подпись, повтор callback,
одноразовый мобильный обмен, удаление аккаунта и запрет чужого Origin.
Google и Steam с реальными аккаунтами требуют отдельного end-to-end прогона после настройки.
В CI собирается debug APK и сохраняется artifact. iOS проверяется на macOS отдельно.

## Публикация веб-интерфейса на GitHub Pages

В Settings → Pages выбрать Source: **GitHub Actions**. Workflow Deploy web app собирает
только dist/ и публикует его. Update meta явно вызывает этот workflow после сохранения
статистики/статуса: это не зависит от того, вызовет ли push встроенного GITHUB_TOKEN
новую сборку Pages. При первой установке запустить Deploy web app вручную.
На GitHub Pages работают статистика и поиск; Google/Steam требуют отдельного HTTPS-сервера.
Чтобы веб-вход работал с cookie, открывать веб-приложение на домене этого сервера.
